# Release validation

## Automated checks

The release process runs:

- Python syntax compilation for all source, test, example, tool, and benchmark files;
- the complete unit-test suite using the included numerical cqlib test double when the native extension is unavailable;
- wheel construction with no dependency resolution;
- installation of the built wheel into an isolated target directory;
- canonical and legacy import smoke tests;
- scans for API keys, absolute user paths, generated bytecode, and internal delivery artifacts;
- archive-content and SHA-256 verification.

## Manual integration evidence

A Tianyan cloud full-amplitude H2 run used the same native-QCIS and QWC path as hardware execution:

- active-space FCI: `-1.137306035753 Ha`;
- best cloud-simulator energy: `-1.136986799379 Ha`;
- absolute error: `0.000319236374 Ha` (`0.319 mHa`);
- measurement groups per evaluation: `5`;
- tasks per evaluation: `5`.

This validates Hamiltonian constants, native gate compilation, measurement-basis changes, grouping, task collection, qubit-order parsing, and energy reconstruction.

Hardware energy accuracy depends on calibration, topology, circuit depth, shot count, and device stability and is not asserted by this software release.
